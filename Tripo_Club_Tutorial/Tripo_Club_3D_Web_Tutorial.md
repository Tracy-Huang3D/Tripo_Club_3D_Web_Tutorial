# Tripo Club — 沉浸式 3D 网站零基础 AI 实作教程

这份教程会带你从一个空文件夹开始，逐步做出一个可在浏览器中运行的沉浸式 3D 网站。你不需要预先会写 JavaScript、React、Three.js 或着色器；主要代码由 Codex 或 Claude Code 完成，你负责描述目标、查看结果，并按每章的清单验收。

成品 Case 02 只用于确认架构和视觉方向。教程中的读者项目是一个全新的独立项目，不依赖成品源码，也不会修改成品项目。

## 开始前先记住

- 全程使用同一个项目文件夹，但每章的 Prompt 都写成了“新对话也能读懂”的形式。
- 一次只做一章。确认“本步完成标志”后，再进入下一章。
- AI Coding Agent 可能采用略有不同的代码组织方式，这是正常的；以可观察到的效果和检查清单为准。
- Agent 提到“本地预览地址”时，通常是类似 `http://localhost:5173/` 的网址。它只在预览服务运行时有效。
- Three.js 负责在网页里绘制 3D 内容；React 负责组织页面；React Three Fiber 让 React 可以更方便地控制 Three.js；Vite 负责启动本地预览和生成可发布的网站。
- 不要把密码、API Key 或私人文件粘贴给 Agent。本教程的基础路线不需要付费 API。

# 01 — 准备工作

### 这一步要做什么？

先准备一个干净的项目文件夹，并让 AI Coding Agent 检查电脑上的网页开发环境。Agent 会在这个空文件夹中建立最小可运行项目，并给你一个本地预览地址；本章还不会制作正式的 3D 页面。

### 操作步骤

1. 在容易找到的位置新建文件夹，建议命名为 `Tripo-Club-Lab`。不要放入成品 Case 02 的源码，也不要把它建在另一个网站项目内部。
2. 在 Codex 或 Claude Code 中选择并打开这个文件夹。确认 Agent 显示的工作目录就是 `Tripo-Club-Lab`。
3. 新建一个任务或对话，复制下面的 Prompt 并发送。
4. 如果 Agent 询问是否允许安装网页依赖，可以允许它从 npm 安装本章列出的公开依赖。不要提供任何密码或 API Key。
5. 等 Agent 返回本地预览地址后，用 Chrome、Edge、Safari 或 Firefox 打开它。预览服务运行期间不要关闭对应任务或终端。
6. 根据检查清单验收。以后即使换成新的 Agent 对话，也要继续打开同一个 `Tripo-Club-Lab` 文件夹。

### 可复制的 Prompt

```text

当前状态：
- 当前打开的文件夹应当是一个空文件夹，项目名为 Tripo Club 教程项目。
- 我们将逐章制作 React + Three.js 沉浸式网站。

7. 启动本地开发预览，实际打开或检查页面是否可访问，并检查浏览器控制台是否有运行时错误。
8. 运行生产构建，确认基础项目能够成功打包。

完成后请用初学者能理解的语言报告：
- 创建了哪些主要文件；
```

浏览器中会出现一个很简单的深色页面，中间显示“TRIPO CLUB / PROJECT READY”。这不是最终设计，它只说明项目、依赖和本地预览已经正常连接。浏览器地址栏中应出现一个本地网址，而不是直接打开某个源代码文件。

- [ ] 浏览器能打开 Agent 提供的本地预览地址。

- [ ] Agent 明确报告生产构建成功，并告诉你如何再次启动预览。

**Agent 说找不到 Node.js 或 npm**

不要让它跳过。请它只提供与你电脑系统对应的 Node.js 当前长期支持版安装步骤，安装完成后重新打开 Agent，再发送本章 Prompt。

**文件夹里出现了第二层同名目录**

请 Agent 把实际项目位置说明清楚。在继续之前，确保以后打开的是包含 `package.json` 和 `src` 的那一层；不要自行随意拖动依赖文件夹。

### 本步完成标志

你能通过本地网址打开准备页，Agent 已确认开发预览与生产构建都正常，并且你知道下次如何重新启动预览。达到这些条件后再进入第 02 章。

# 02 — 创建第一个 3D Hero

### 这一步要做什么？

这一章会把准备页升级为全屏 3D Hero，也就是网站打开后看到的第一屏。我们先建立一个持续存在的 WebGL 画布、中央标题和最小 HUD；液态、霓虹和滚动动画会在后续章节加入。

### 操作步骤

1. 保持第 01 章的项目文件夹不变，确认本地预览可以重新启动。
2. 在新的 Agent 对话中也可以操作，但必须让它读取当前项目文件，而不是重新创建项目。
3. 发送下面的 Prompt。Agent 修改期间不要手动删除 `src` 或 `package.json`。
4. 打开 Agent 返回的预览地址，先观察 3D 背景是否在运行，再检查文字和四角信息。
5. 调整浏览器宽度，并使用浏览器设备模式查看约 390×844 的手机尺寸。

### 可复制的 Prompt

```text
请继续当前 Tripo Club 教程项目。先检查 package.json、src 目录和现有预览，确认这是第 01 章建立的 Vite + React 项目；不要重新初始化，也不要删除可用配置。

当前已完成：
- Vite + React 基础项目；
- three 和 @react-three/fiber 已安装；
- 深色 PROJECT READY 准备页；
- 本地预览和生产构建可用。

本章目标：制作第一个全屏 3D Hero，建立后续章节要继续使用的持久 Canvas 架构。

请实际实现：
1. 建立占满视口的 Hero。页面背景接近黑色，整体方向是实验性数字展览，而不是普通企业落地页。
2. 在 Hero 中加入一个 React Three Fiber Canvas。设置合理的透视相机、设备像素比上限和基础灯光，在场景中加入少量真正的 3D 几何体、细线或粒子，让我能确认 WebGL 正在渲染。此时效果应克制，不要加入霓虹后期或液态着色器。
3. Canvas 必须成为后续持续使用的同一个场景容器，不要为每种效果建立多个重叠 Canvas，也不要在普通状态下反复卸载重建。
4. 在 3D 画布上方建立 HTML 界面层：中央两行大标题“TRIPO”和“CLUB”；左上角小型“TRIPO CLUB”品牌；右上角“MENU”文字；底部加入“SCROLL TO ENTER”和“01 / 03”一类的最小 HUD。MENU 本章只作为视觉标签，不要伪装成已经可用的复杂菜单。
5. 中央标题要使用唯一一个语义 h1。装饰性重复文字需要对屏幕阅读器隐藏，避免同一个标题被朗读两次。
6. 正确处理层级：Canvas 在背景，文字和 HUD 清晰位于上方；装饰层不能挡住未来按钮或页面操作。
7. 做响应式布局。桌面端标题有视觉冲击力；在 390×844 手机尺寸中标题完整可读，不与顶部和底部 HUD 重叠，不产生横向滚动。触屏设备不依赖鼠标才能看到主要内容。
8. 支持 prefers-reduced-motion：减少动态时，场景仍然可见和可读，可以停止非必要的持续动画。
9. 不从 CDN 加载 React、Three.js 或字体；继续使用项目依赖。组件和样式应清晰组织，便于后续加入共享 pointerRef 和 scrollRef。

请启动本地预览并实际检查：
- WebGL 场景是否渲染；
- 标题和 HUD 是否清晰；
- 桌面与 390×844 布局；
- 浏览器控制台；
- npm run build。

修复普通问题后，报告主要文件、检查结果和预览地址。不要加入液态扭曲、霓虹视差、滚动转场、活动轮播或 GLB 字体。完成本章后停止。
```

### 你应该看到什么？

页面会铺满浏览器，背景是深色 WebGL 场景，能看到细微移动或具有透视关系的 3D 元素。中央是清楚的两行“TRIPO / CLUB”，四周只有少量类似展览导视的文字。缩窄页面时，标题会适当缩小，HUD 仍贴近安全边缘。

### 检查清单

- [ ] 背景不是静态截图；能看出 3D 元素或粒子由 WebGL 渲染。
- [ ] “TRIPO / CLUB”完整、清楚，页面上没有第二个可见的大标题。
- [ ] 左上品牌、右上 MENU、底部提示和页码均可见。
- [ ] 390×844 尺寸下没有裁切、重叠或横向滚动。
- [ ] 减少动态模式下仍能看到完整页面，而不是黑屏。
- [ ] Agent 报告浏览器控制台无运行时错误，生产构建通过。

### 常见问题

**只看到文字，看不到 3D 背景**

这通常是相机、物体位置、Canvas 高度或图层顺序问题。发送：

```text
当前 Hero 的 HTML 文字可见，但 WebGL 3D 内容不可见。请检查 Canvas 实际尺寸、相机朝向、物体是否位于相机前方、材质是否需要灯光，以及 CSS 层级。请用明显但不破坏设计的临时检查方式定位原因，修复后移除调试内容，并重新验证桌面和手机。不要开始下一章。
```

**页面变成全白或控制台出现 WebGL 错误**

请把控制台第一条错误原样交给 Agent，让它从第一条错误开始修复。不要连续安装多个未知库来碰运气。

**手机标题挡住底部提示**

请 Agent 使用视口高度安全单位、`clamp()` 字号和独立的手机断点调整，而不是直接隐藏全部 HUD。

### 本步完成标志

你能在桌面和手机尺寸中打开全屏 Hero，WebGL 背景、中央标题和最小 HUD 都正常显示；刷新页面后仍能稳定加载。

# 03 — 设计 Hero 的空间层次

### 这一步要做什么？

现在要让页面从“有一个 3D 背景”变成“有前景、中景和背景的空间”。这一章主要调整排版、网格和技术性装饰，让中央标题成为视觉中心，同时保持整个构图在手机上仍然清楚。

### 操作步骤

1. 打开第 02 章的 Hero，保存一张修改前截图，便于比较。
2. 把下面的 Prompt 发给 Agent。它应当在现有 Canvas 和组件上继续工作，而不是另做一张新页面。
3. 完成后先静止观察：你应该能立刻分辨中央标题、空间网格和边缘 HUD 的优先级。
4. 分别查看宽屏、普通笔记本和 390×844 手机尺寸。

### 可复制的 Prompt

```text
请继续当前 Tripo Club 教程项目，并先阅读现有 App、Scene、Hero UI 和全局样式。保留第 02 章已经工作的单一持久 WebGL Canvas、中央 TRIPO / CLUB 语义标题、基础 3D 元素和最小 HUD。

当前已完成：
- 全屏深色 Hero；
- 持久 React Three Fiber Canvas；
- 中央 TRIPO / CLUB 标题；
- 左上品牌、右上 MENU、底部滚动提示和页码；
- 桌面和手机基础布局。

本章目标：建立清楚的前景、中景、背景关系和实验性编辑排版，不添加新交互。

请实际实现：
1. 将大标题设计成两行高对比的编辑式排版。使用粗重几何无衬线风格、紧凑行距和响应式字号，保持“TRIPO”在上、“CLUB”在下；桌面有冲击力，手机完整可读。
2. 把空间分成三层：
   - 前景：四周小型 HUD、坐标、刻度或十字标记；
   - 中景：中央标题及一条很短的说明或 kicker；
   - 背景：现有 3D 内容、稀疏粒子和具有透视感的网格。
3. 加入克制的技术/展览元素，例如透视地面网格、测量刻度、十字定位点，以及低对比度的 CREATE、SHARE 等背景字样。它们都是装饰，不能抢过标题，也不能被屏幕阅读器重复朗读。
4. 通过大小、亮度、透明度和空间位置建立层级，不要把内容做成卡片，不要使用 SaaS 仪表盘风格，不要堆满屏幕。
5. 保持背景足够深，主标题接近白色。暂时只允许非常轻的冷色提示，不要在本章完成霓虹灯光或 bloom。
6. 保留一个语义 h1，保持键盘与屏幕阅读器可用。装饰元素使用 aria-hidden 或等效处理。
7. 做响应式检查：390×844 下减少装饰数量和网格密度，确保标题不碰顶部品牌、MENU 或底部 HUD；页面不能横向溢出。
8. 不要改变 Canvas 架构，不要添加第二套动画循环。若已有很轻的场景运动，可以保留；本章不做鼠标跟随和滚动动画。

请启动本地预览并实际检查宽屏、普通桌面和 390×844；检查控制台和生产构建。完成后报告主要视觉调整、文件变化、已验证项目和预览地址。

不要添加液态扭曲、指针视差、滚动转场、活动轮播、全屏详情或 GLB 字体。完成空间层次后停止。
```

### 你应该看到什么？

中央“TRIPO / CLUB”仍然最醒目，但它不再像单独贴在屏幕上的文字。标题后方会出现向深处延伸的网格和稀疏 3D 元素，屏幕边缘有低调的定位标记和背景词，形成数字展览入口的感觉。所有辅助元素都比标题更暗、更小。

### 检查清单

- [ ] 第一眼仍然先看到“TRIPO / CLUB”，而不是网格或装饰字。
- [ ] 能清楚分辨前景 HUD、中景标题和背景 3D 空间。
- [ ] 背景网格有透视方向，不像普通方格壁纸盖住整页。
- [ ] 边缘装饰没有遮挡文字或未来可点击区域。
- [ ] 390×844 下标题、品牌、MENU 和底部 HUD 不重叠。
- [ ] 页面仍只有一个可访问的主标题。

### 常见问题

**背景元素太多，标题不够清楚**

让 Agent 降低背景的透明度、线条密度和字号，而不是给标题添加夸张阴影：

```text
当前 Hero 的网格和技术装饰抢过了主标题。请重新建立视觉层级：主标题保持最高对比度，背景网格和大号装饰词明显降到低对比，四周标记更小更稀疏。保留空间感，不要通过卡片或大面积黑色遮罩解决。完成后重新检查桌面和 390×844。
```

**手机上出现横向滚动**

请 Agent 找到实际溢出的元素，调整其宽度、定位和 `overflow`，不要只在整个页面上粗暴隐藏问题后停止检查。

**标题字体与预期不同**

不同电脑的系统字体会有差异。本阶段可以使用可靠的字体回退组合；不要为了一个字体从不明网站下载文件。后续第 13 章会使用真正的 GLB 3D 字体模型。

### 本步完成标志

Hero 在静止状态下已经呈现明确的空间层次和编辑式排版，而且宽屏与手机都保持清晰。此时即使还没有鼠标互动，页面也应像一个完整的数字展览入口。

# 04 — 添加鼠标液态交互

### 这一步要做什么？

这一章会让 WebGL 背景在鼠标附近产生柔和的弯曲和液态反馈。你不需要学习着色器公式，只要知道它是一小段交给显卡执行的绘制规则；中央文字和 HUD 仍然保持清楚，不会像果冻一样剧烈变形。

### 操作步骤

1. 确认第 03 章页面能够稳定运行，再将下面的 Prompt 发送给 Agent。
2. 实现完成后，把鼠标在标题周围慢慢移动，再快速横向移动一次。
3. 将鼠标停住并移出窗口，观察扭曲是否平滑减弱。

# 05 — 霓虹环境与空间视差

### 这一步要做什么？

这一章会用紫色、蓝色和青色建立霓虹空间，并让不同层跟随鼠标产生不同幅度的移动。所谓“视差”，就是近处和远处移动得不一样，因此平面屏幕会显得更有深度。

### 操作步骤

1. 打开第 04 章页面，确认液态效果仍然正常。
2. 发送下面的 Prompt，让 Agent 复用已经存在的指针状态，而不是再建立一套鼠标系统。
3. 预览完成后，缓慢把鼠标移到屏幕四角，观察背景、中景标题和前景 HUD 的相对移动。
4. 快速移动鼠标，确认液态反馈和视差同时存在但各自克制。
5. 将窗口缩到手机尺寸，并检查主标题对比度。

# 07 — 制作 3D 环形活动轮播

### 这一步要做什么？

这一章会让 Event Space 中的四个活动框架真正沿着 3D 圆环旋转。继续向下滚动时，活动会依次来到前方；停止滚动后，页面会温和地对齐到最近一站，向上滚动则按相反顺序返回。

### 操作步骤

1. 从页面顶部滚到第 06 章的 Event Space，确认四个框架都存在。
2. 发送下面的 Prompt。Agent 应在现有四个 3D 对象上工作，不要把它们改成横向 HTML 卡片列表。
3. 完成后，从 Hero 进入 Event Space，再用短距离滚动依次查看四个活动位置。
4. 每次接近一个活动后停止滚动，观察是否平滑吸附到最近的正面位置。
5. 从 EVENT 04 向上滚回 EVENT 01，再继续回到 Hero。

### 常见问题

**活动顺序或计数对不上**

```text
当前 3D 轮播中，正面的活动与 HUD 计数不一致。请统一 carouselProgress、圆环旋转角和 activeIndex 的映射，使用同一个活动数组作为顺序来源；逐一验证 0、1/3、2/3、1 四个停靠值。修复后检查正向和反向，不要添加下一章内容。
```

**停止滚动后页面来回拉扯**

通常是吸附动画与 scroll 监听互相启动。请 Agent 在吸附期间记录状态，忽略自身产生的微小滚动更新，并在 wheel、touch、按键输入时取消；吸附完成后清理计时器。不要让多个定时器同时控制窗口位置。

**EVENT 04 之后仍被强制拉回轮播**

要求 Agent 为吸附设置严格的起止范围。只有滚动目标和当前位置都在 carousel 区间内时才能吸附；越过末端后必须释放控制权，为后续章节保留空间。

**侧面活动全部消失或变成一条线**

请检查活动自身朝向、圆环半径、相机距离和透明度的深度计算。侧面需要有透视感，但仍应看出它是一个空间框架。

**手机滚一次就跨过多个活动**

请 Agent 根据移动端滚动距离扩展每个停靠点之间的物理页面长度，并降低吸附的触发侵略性，不要拦截 `touchmove`。
